# 操作系统：进程同步机制

## 一、临界区与临界资源

临界资源（Critical Resource）是指一次仅允许一个进程使用的共享资源。
临界区（Critical Section）是访问临界资源的那段代码。

进程进入临界区必须遵循以下准则：
- **空闲让进**：当临界区空闲时，允许一个请求进入临界区的进程立即进入。
- **忙则等待**：当已有进程进入临界区时，其他试图进入的进程必须等待。
- **有限等待**：对请求访问的进程，应保证在有限时间内进入临界区。
- **让权等待**：当进程不能进入临界区时，应立即释放处理器，防止进程忙等待。

## 二、互斥实现方法

### 1. 软件方法：Peterson 算法

Peterson 算法适用于两个进程互斥进入临界区，使用两个变量：`flag[2]` 和 `turn`。

```c
// Pi 进程
do {
    flag[i] = true;
    turn = j;
    while (flag[j] && turn == j); // 等待
    // 临界区
    flag[i] = false;
    // 剩余区
} while (true);
```

Peterson 算法满足互斥、空闲让进、有限等待三个条件，但不满足让权等待（存在忙等）。

### 2. 硬件方法：Test-and-Set 指令

```c
bool TestAndSet(bool *lock) {
    bool old = *lock;
    *lock = true;
    return old;
}
```

使用 TSL 指令实现互斥：

```c
while (TestAndSet(&lock)); // 忙等待
// 临界区
lock = false;
```

### 3. 信号量机制

信号量（Semaphore）由 Dijkstra 提出，是一个整型变量，只能由 P、V 操作访问。

```c
// 记录型信号量
typedef struct {
    int value;
    struct process *list;
} semaphore;

void P(semaphore *S) {
    S->value--;
    if (S->value < 0) {
        block(S->list); // 阻塞并插入等待队列
    }
}

void V(semaphore *S) {
    S->value++;
    if (S->value <= 0) {
        wakeup(S->list); // 唤醒等待队列中的一个进程
    }
}
```

## 三、经典同步问题

### 生产者-消费者问题

设缓冲区大小为 n，需要三个信号量：
- `mutex = 1`：互斥访问缓冲区
- `empty = n`：空缓冲区数量
- `full = 0`：满缓冲区数量

```c
// 生产者
P(empty);
P(mutex);
// 放入产品
V(mutex);
V(full);

// 消费者
P(full);
P(mutex);
// 取出产品
V(mutex);
V(empty);
```

### 读者-写者问题

允许多个读者同时读，但写者必须独占访问。

## 四、死锁

死锁产生的四个必要条件：
1. **互斥条件**：资源一次只能被一个进程占用。
2. **占有并等待**：进程持有资源同时又在等待其他资源。
3. **不可剥夺**：已获得的资源不能被强行剥夺。
4. **循环等待**：存在进程-资源的循环等待链。
